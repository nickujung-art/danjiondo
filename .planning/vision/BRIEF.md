## 한 줄 정의

**창원·김해 사람들이 가장 먼저 읽는 부동산 미디어**

---

## 1. 문제 — 지금 단지온도는 뭐가 문제인가

- 호갱노노 따라 기능만 붙인 "기능 집합체"가 돼버렸다
- 누구를 위한 서비스인지 불명확
- 전국 서비스 대비 기능 부족, 카페 대비 깊이 부족
- **집 살 생각 없으면 들어올 이유가 없다**

---

## 2. 방향 — 왜 로컬 미디어인가

| 자산 | 의미 |
|------|------|
| 창원부동산이야기 카페 **20만 회원** | 이미 독자가 있다 |
| 창원·김해 다루는 로컬 미디어 **경쟁자 0** | 선점 가능 |
| 호갱노노가 절대 못 만드는 **우리 동네 이야기** | 차별화 |

→ 데이터 기능은 콘텐츠 안에 녹인다. 기능 페이지가 아니라 기사 페이지로.

---

## 3. 브랜드 — "창부레터"

- **어원**: 창원부동산이야기 + 레터(뉴스레터)
- **도메인**: changbuletter.com
- **레터**라는 이름이 이메일 구독을 자연스럽게 암시
- 카페 20만 회원 → 뉴스레터 독자로 전환하는 흐름

> **제1 옵션 확정** — 이 이름 기준으로 진행

---

## 4. 타겟

| 우선순위 | 대상 | 특징 |
|---------|------|------|
| **MAIN** | 창원·김해 거주 30~50대 | 이미 내 집 있음, 카페 회원, 동네 소식 소비 |
| **MAIN** | 이 지역 처음 오는 사람 | 삼성·포스코 임직원 이전, 학군·교통 정보 필요 |
| SUB | 로컬 투자자 | 갭투자·재건축, 데이터 기반 |

---

## 5. 콘텐츠 4종

| 콘텐츠 | 주기 | 채널 | 역할 |
|--------|------|------|------|
| 주간 실거래가 카드뉴스 | 주 1회 | 인스타 + 카페 | 바이럴, 이미 자동화됨 |
| 기획기사 (동네 분석) | 월 2~4회 | 사이트 + 카페 | 구글 유입·신뢰도 핵심 |
| 랭킹 인포그래픽 | 주 1회 | 인스타 스토리 | 거래량·상승률 TOP 5 자동 생성 |
| 지역 가이드 | 월 1~2회 | 사이트 | 이전자 수요, 롱테일 SEO |

## 6. 사이트 구조 변경

```
기존: 단지 검색 중심
변경: 콘텐츠 피드 중심 홈 + 콘텐츠 섹션 신설

신규: 홈(재설계), 콘텐츠, 지역 가이드
유지: 단지 검색, 마이페이지
depth↓: 지도 (메인 네비에서 빠짐)
```

---

## 7. 유저 동선 (4단계 퍼널)

```
진입 → 랜딩 → 탐색 → 전환/락인

[인스타·카페] → 콘텐츠 상세(★ 주요 랜딩)
[구글 검색]   → 지역 가이드
[이메일]      → 콘텐츠 상세 (재방문)

락인 포인트:
  즉시 투표 참여 → 커뮤니티
  북마크 저장    → 소셜 로그인 → 회원가입
  뉴스레터 구독  → ★ 핵심 전환
```

**콘텐츠 상세 페이지가 가장 중요한 랜딩 페이지**  
인스타 링크 클릭 → 콘텐츠 상세 → 구독 CTA가 기본 퍼널.

## 8. 다음 단계 (우선순위)

1. **콘텐츠 상세 페이지** (최우선) — 카드뉴스 풀뷰 + 단지 데이터 + 구독 CTA
2. **홈 피드형 재설계** — 검색창 → 콘텐츠 피드, 네비에 '콘텐츠' 추가
3. **이메일 뉴스레터 발송** — Resend API, 주간 큐레이션 이메일 → 창부레터 브랜드 완성
4. **슬라이드 카드뷰어 + 커뮤니티** — 체류시간·재방문율 핵심
5. **지역 가이드 신설** — 경쟁자 없는 SEO 자산

## 10. 콘텐츠 상세 페이지 기획 (2026-07-01)

**URL**: `/content/[slug]`

### 페이지 구성 (위 → 아래)

| 영역 | 내용 |
|------|------|
| 헤더 | 태그, 제목, 날짜 |
| 메인 콘텐츠 | 타입별 분기 |
| 관련 단지 | 카드 여러 개 (다대다) |
| VS 투표 | 로그인 필수, 즉시 결과 공개 |
| 뉴스레터 CTA | 구독 유도 |
| 다음 콘텐츠 | 추천 2~3개 |

### 콘텐츠 타입 2종

- **카드뉴스** → HTML 슬라이드 뷰어 (PNG 아닌 HTML 렌더링, SEO 대응)
- **기획기사** → Tiptap 블록 에디터, JSON 저장 (텍스트 + 이미지 블록)

### VS 투표

- 어드민에서 질문 제목 / 왼쪽 옵션 / 오른쪽 옵션 직접 입력
- 로그인 후 투표 → 즉시 퍼센트 바 공개
- 락인 포인트 역할 (비로그인 → 로그인 유도)

### DB 구조

```
contents          — id, slug, type(card_news|article), title, tag, body(JSON), published_at
                    vote_question, vote_left, vote_right
content_complexes — content_id ↔ complex_id (다대다)
content_votes     — content_id, user_id, choice(left|right)
```

### 콘텐츠 상세 페이지 세부 결정 (2026-07-29 확정)

| 항목 | 결정 |
|------|------|
| 랭킹 인포그래픽 타입 | **`card_news` 타입에 통합**, `tag="랭킹"`으로 구분 — 둘 다 자동생성·멀티슬라이드
  구조가 동일해 HTML 슬라이드뷰어 컴포넌트를 그대로 재사용. 인스타 스토리용 9:16
  비율은 콘텐츠 타입이 아니라 템플릿 선택(레이아웃)으로만 분기 |
| 공유 기능 | **카카오톡 공유 + 링크 복사 버튼 둘 다 추가** (Kakao SDK + clipboard API) —
  바이럴 성장 전략과 직결되는 저비용 고효과 기능 |
| OG 이미지 | **카드뉴스는 첫 슬라이드를 OG 이미지로 사용.** 기획기사(article)는 첫
  슬라이드가 없으므로 제목 기반 생성 OG 카드(`@vercel/og` 등)로 별도 처리 |

## 12. 인프라·연동 결정 (2026-07-29)

카드뉴스 파이프라인 실사용 확인: `card-news/`가 별도 Node 프로젝트로
`fetch-data.js`(데이터 조회) → `templates.js`(HTML 생성) → `capture.js`
(Puppeteer PNG 캡처) → `post-instagram.js`(인스타 포스팅) 단계로 분리돼
있음. 창부레터는 `capture.js` 단계를 건너뛰고 `fetch-data.js`+`templates.js`를
재사용해 **HTML로 직접 렌더링**하면 됨 — §10의 "카드뉴스 → HTML 슬라이드
뷰어(PNG 아닌 HTML, SEO 대응)" 계획과 정확히 일치.

| 항목 | 결정 |
|------|------|
| Supabase 공유 | **같은 프로젝트 재사용** — `favorites`/`ad_campaigns`에 이미 쓰는
  `site_id` 분리 패턴을 확장, 창부레터용 `site_id='changbuletter'` 추가 예정
  (`supabase/migrations/20260715000001_realtrade_story_site_scoping.sql` 패턴 참고).
  카드뉴스 원본 데이터(`transactions`/`complexes`)도 별도 동기화 없이 바로 조회 가능 |
| 관련 단지 카드 ↔ 실거래이야기 연동 | **가격 미리보기 카드** — 단순 링크가 아니라
  실거래이야기 API로 최신가·변동률을 가져와 카드에 표시(예: "84A 8.5억, 최근 3개월
  -2%"). **다음 단계에서 두 사이트 간 API 계약(엔드포인트·응답 스키마·인증 방식)을
  실거래이야기 쪽과 맞춰 설계해야 함** — 창부레터 부트스트랩 시점에 realtrade-story
  담당 세션과 조율 필요 |
| 인증/구독 분리 | 뉴스레터 구독은 **로그인 없이 이메일만**으로 전환장벽 최소화.
  VS 투표·북마크처럼 로그인이 필요한 기능은 danjiondo/realtrade-story와 공유하는
  기존 계정 시스템(`auth.users`/`profiles`) 재사용 |
| 저장소 부트스트랩 | realtrade-story와 동일 패턴 — **별도 세션/도구에서 GSD
  `/new-project`**로 시작. 이 bds 세션과 무관하게 진행 |
