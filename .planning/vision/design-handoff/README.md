## About the Design Files

**이 번들의 HTML/JSX 파일은 프로덕션 코드가 아니라 "디자인 레퍼런스"입니다.** 의도된 외관과 동작을 보여주는 프로토타입이며, 그대로 복사해 배포할 코드가 아닙니다.

작업 방식:

- 대상 코드베이스가 이미 있다면(Next.js, React, Vue, Svelte 등) **그 환경의 기존 패턴·컴포넌트·스타일 시스템으로 이 디자인을 재현**하세요.
- 아직 환경이 없다면, 이 프로젝트에 가장 적합한 프레임워크를 선택해 구현하세요. **권장: Next.js (App Router) + TypeScript + CSS Modules 또는 Tailwind.** SEO가 이 서비스의 핵심 유입 경로(롱테일 검색)이므로 **SSR/SSG가 가능한 프레임워크가 필수**입니다.
- 프로토타입은 CDN React + Babel in-browser로 동작합니다. 이는 미리보기 편의를 위한 것이며 프로덕션에서는 반드시 빌드 타임 트랜스파일로 대체하세요.
- 목업 데이터(`data.js`)는 실제 창원·김해 지명·단지명을 사용한 **가상 데이터**입니다. 실 데이터 소스(국토부 실거래가 API 등)로 교체해야 합니다.

## Fidelity

**High-fidelity (하이파이).** 색상·타이포그래피·간격·인터랙션이 모두 최종 값입니다. 아래 문서의 수치를 **그대로** 사용하세요 — 4/8px 그리드로 반올림하지 마세요 (예: `12.5px`, `14.5px`, `10.5px` 같은 값이 의도적으로 쓰였습니다).

레이아웃 구조와 반응형 브레이크포인트도 그대로 따르되, 접근성·시맨틱 마크업은 프로덕션 기준으로 강화하는 것을 권장합니다.

- 메인+사이드 → 1열, 히어로 → 1열, 3열 그리드 → 2열, 랭킹 스트립 5칩 → 2열, CTA 바 → 1열, 푸터 4열 → 2열, 네비 링크 숨김

> ⚠️ **태블릿(768px)과 모바일 웹(390px) 중간 대응이 프로토타입에 없습니다.** 모바일은 별도 앱 셸(`mobile.html`)로만 존재합니다. 실제로는 하나의 반응형 웹으로 구현할 가능성이 높으므로, 데스크톱 컴포넌트가 모바일 목업의 레이아웃으로 수렴하도록 브레이크포인트를 추가 설계해야 합니다. 이 부분은 **디자이너와 협의 필요**.

## State Management

프로토타입의 상태 (프로덕션에서는 라우터 + 서버 상태로 대체):

**데스크톱 `App`**
| State | Type | 역할 |
|-------|------|------|
| ~~`variation`~~ | ~~`'A' \| 'B'`~~ | **2026-07-29 제거됨** — 변형 A 확정으로 토글 자체가 코드에서 삭제됨(더 이상 존재하지 않음) |
| `route` | `'home' \| 'article'` | → URL 라우팅으로 대체 |
| `article` | `object \| null` | 선택된 콘텐츠 → `/content/[slug]` 데이터 페칭으로 대체 |
| `modal` | `{open, email}` | 구독 모달 |
| `toast` | `string \| null` | 1.8초 자동 소멸 |

**모바일 `MobileApp`**: `route`, `article`, `sheet`, `toast`, `tab` (탭바 활성 상태 — `route`와 동기화)

**카드뉴스 뷰어**: `index` (현재 슬라이드). 모바일은 스크롤 위치에서 파생.

### 데이터 요구사항 (`data.js` 구조 참고)

| 키 | 내용 | 실 데이터 소스 |

**"관련 단지" 가격 미리보기 데이터 소스** (2026-07-29 추가): 창부레터·bds·실거래이야기가
같은 Supabase 프로젝트를 공유하므로 `complex_id`가 세 프로젝트에서 동일한 값이다.
별도 HTTP API 계약 없이 창부레터가 `complexes`/`transactions`를 직접 조회해 최신가·
변동률을 가져오면 된다(`cbl-article.jsx`의 `RelatedComplex` 참고). 실거래이야기가
이미 쓰는 가격 계산 로직(`avg_sale_per_pyeong`, `price_change_30d` 등)을 재사용할 것.

## Content Fundamentals (카피 작성 규칙)

목업의 카피는 브랜드 톤을 담고 있으므로 구현 시 그대로 유지하세요.

- **어미**: `~해요` 체 (친근하지만 정중). 예: "매주 월요일 아침, 우리 동네 소식을 보내드릴게요." / "언제든 한 번의 클릭으로 구독을 해지할 수 있어요."
- **제목**: 단정하고 짧은 서술문 또는 질문. 예: "왜 중동이 올랐나 — 유니시티가 바꾼 창원 서북부 지형도" / "장유 신도시, 김해의 강남이 될 수 있을까"
- **1인칭/2인칭**: "우리 동네" — 지역 공동체의 일원으로 말합니다. 사용자를 "고객"이라 부르지 않습니다.
- **숫자 표기**: 한국식 억/만원 단위 (`8억 9,000만원`), 변동률은 `▲ 2.3%` / `▼ 0.4%` 기호 + 소수 1자리
- **날짜**: `6.20` (짧은 형식), 주차는 `6월 3주차 (6.16–6.22)`
- **신뢰 신호**: "광고 없음", "구독자 4,820명", "20만 회원" 같은 구체적 수치. 과장 표현·감탄부호 남용 금지
- **금지**: 이모지 장식, "AI 추천!" 같은 기술 자랑, 투자 권유·수익 보장 표현. 면책 문구는 푸터에 항상 유지
- **대소문자/영문**: 영문은 최소화. 서비스명은 항상 한글 `창부레터.`
