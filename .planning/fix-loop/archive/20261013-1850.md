## 문제 정의

`data_sources` 의 실패 기록이 두 갈래로 틀어져 있다.

1. **MOLIT 실패가 `consecutive_failures` 를 올리지 않는다.** 10-13 현재 `molit_trade`·`molit_villa_trade` =
   `last_status='failed'`, `consecutive_failures=0`. 실패를 쓰는 경로 두 곳이 모두 카운터를 건드리지 않는다.
   - `molit-daily.yml` verdict 단계: 3회 전부 차단 시 curl PATCH 로 `last_status`·`error_message` 만 씀
   - `scripts/backfill-realprice.ts` 끝부분: 실패율 30% 초과(aborted) 시 `baseUpdate` 에 카운터 없음
   → 외부 감시견(ax-sub)의 `consecutive_failures > 0` 규칙이 이 소스에서 죽어 있다.
   (저장소 안에서 이 컬럼을 읽는 곳은 admin/data-ops 표시뿐이다 — 규칙은 외부에 있다.)
2. **`markCronFailed()` 가 실패에도 `last_synced_at = now()` 를 민다.** 매일 실패해도 "최종 갱신"이
   오늘로 찍혀 경과시간 기반 판정(외부 감시견)이 걸리지 않는다. admin/status 배지는 `failed` 를 지연보다
   먼저 보므로 UI 에서는 이미 '실패'로 보인다 — 거짓말하는 것은 시각 컬럼이다.
   backfill-realprice 의 aborted 경로도 같은 문제(`syncedAt` 을 실패에도 씀).

## 해결 접근법

- **`last_synced_at` 의 의미를 "마지막으로 데이터가 들어온 시각"으로 고정한다.**
  - `markCronFailed`: `last_synced_at` 을 쓰지 않는다. `last_status`·`consecutive_failures+1`·`error_message` 만.
  - `markCronSuccess`/`markCronPartial`: 그대로 (둘 다 실제로 데이터가 들어왔다).
- `backfill-realprice.ts`: 손으로 짠 update 두 개를 `markCronStatus(supabase, id, finalStatus, errorMessage)` 로 교체.
  카운터 증가·성공 시 리셋·실패 시 타임스탬프 유지가 한 곳으로 모인다. (스크립트는 이미 `createClient<Database>` 라 타입 맞음)
- `molit-daily.yml` verdict: PATCH 전에 현재 `consecutive_failures` 를 GET(jq) 해서 +1 로 쓴다. `last_synced_at` 은 원래 안 씀 — 유지.
  GET 실패가 `bash -e` 로 보고 전체를 죽이지 않게 `|| prev=0` + 숫자 검증.

### 리뷰 반영 (code-reviewer)

- `markCronPartial`: errorMessage 미지정 시 `error_message: null` 로 지운다. 안 그러면 aborted 다음 partial 에
  낡은 실패 사유가 남는다(backfill 기존 동작이 null 이었다). backfill 은 partial 에 `N/M 실패` 메시지를 넘긴다.
- backfill: `errorMessage ?? undefined` 로 타입 맞춤, 보고 실패(false) 시 경고만 남기고 종료 코드는 바꾸지 않는다.
- 테스트 스텁에 `select().eq().maybeSingle()` 경로 추가 (오답노트 #001 — 목 화이트리스트).
- **첫 실행부터 실패 → `last_synced_at` null → admin/status 가 '미실행'(회색)으로 표시** (null 체크가 failed 보다 먼저).
  현재 null 행은 `school_alimi` 하나(보고 자체를 안 하는 소스)라 당장 영향은 없고 신규 소스에만 해당.
  → 처리 방식 사용자 결정 대기: (a) `cronBadge` 순서 변경(5번째 파일) / (b) null 일 때만 now() 채움

## 예상 변경 사항

- 영향받는 호출부: rankings · notify-worker · markCronStatus 경유(monthly-commentary 등). 실패 시 `last_synced_at` 이
  더 이상 갱신되지 않을 뿐, 배지는 `last_status='failed'` 를 먼저 보므로 '실패' 표시는 그대로.
- 테스트: markCronFailed 가 `last_synced_at` 을 보내지 않고 `consecutive_failures: prev+1` 을 보내는지.
- DB 스키마 변경 없음.
