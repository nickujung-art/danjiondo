# getActiveAds 가 site_id 로 거르지 않는다

## 문제 정의

`src/lib/data/ads.ts:63` 의 `getActiveAds` 가 `ad_campaigns` 를 `placement`·`status`·
기간으로만 거른다. `site_id` 조건이 없다.

`ad_campaigns` 는 danjiondo · realtrade-story · changbuletter 가 **한 Supabase 프로젝트를
공유**하는 테이블이다(20260715000001 · 20260730000001). 사이트 분리는 RLS 가 아니라
애플리케이션 코드 책임이다 — `src/lib/data/site.ts` 가 이걸 명시하고 `SITE_ID` 상수를
제공한다. favorites 계열 5개 파일은 2026-07-31 에 이 상수를 적용했는데
**`ad_campaigns` 는 빠졌다.**

지금은 캠페인 9건이 전부 `danjiondo` 라 증상이 없다. 그러나 realtrade-story 광고를
`approved` 로 만드는 순간 **그 광고가 danjiondo 홈·지도·사이드바에 그대로 노출된다.**
방금 만든 `record_ad_event` RPC 가 realtrade-story 광고 적재를 여는 참이라
캠페인 생성이 임박했다 — 그 전에 막아야 한다.

동일 유형의 선례가 이미 있다: favorites 가 같은 구조로 새서, realtrade-story 즐겨찾기
4건이 danjiondo 화면에 그대로 보이고 `removeFavorite` 이 남의 행까지 지웠다.

## 수정 범위

| 파일 | 변경 |
|---|---|
| `src/lib/data/ads.ts` | `SITE_ID` import + `getActiveAds` 에 `.eq('site_id', SITE_ID)` |
| `src/__tests__/ads-site-scope.test.ts` (신규) | CI 에서 도는 회귀 테스트 |

## 해결 접근법

기존 `SITE_ID` 패턴을 그대로 따른다(`favorites.ts` · `profile.ts` · `rankings.ts` ·
`digest.ts` 와 동일한 `.eq('site_id', SITE_ID)`). 새 개념을 만들지 않는다.

### 🔴 테스트를 왜 새로 만드나

`src/__tests__/ads.test.ts` 의 `getActiveAds` 통합 테스트는 `describe.skipIf(!SKEY)` 라
**CI 에서 통째로 스킵된다.** 거기에 케이스를 더해도 회귀를 잡지 못한다.
그래서 목 클라이언트로 **쿼리에 어떤 조건이 붙었는지**를 검사하는 테스트를 따로 만든다.
DB 없이 항상 실행된다.

같은 테스트로 CLAUDE.md CRITICAL 인 `status='approved'` + 기간 조건도 함께 잠근다 —
셋 다 "빠뜨려도 조용히 통과하는" 같은 부류다.

## 예상 변경 사항

```
ads.ts   import { SITE_ID } from '@/lib/data/site'
         getActiveAds 쿼리에 .eq('site_id', SITE_ID) 한 줄
신규     ads-site-scope.test.ts — 4개 불변식(site_id·status·starts_at·ends_at) 검사
```

정상 동작 변화 없음: 현재 캠페인 9건이 전부 danjiondo 라 반환 결과가 동일하다.

## 하지 않는 것 (별건으로 보고)

어드민 경로는 건드리지 않는다 — `getAllAdCampaigns` · `getAdRoiStats` ·
`getAdCampaignById` · `admin/ads` · `admin/layout` · `admin/status` · `ad-actions`.
전부 service role 이라 전 사이트를 본다.

realtrade-story 는 `site_admin_roles` 기반 **자체 어드민 경로**가 따로 있다
(20260728074553). 그러니 bds 어드민이 전 사이트를 보는 게 **의도인지 사고인지**가
갈린다 — 소유자 감독 목적이면 맞고, 아니면 틀렸다. 사용자 판단이 필요하므로
이번 수정에 섞지 않는다. 공개 노출 결함과 성격이 다르다.
