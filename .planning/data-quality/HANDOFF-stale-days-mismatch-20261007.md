# 인계 — 월간 AI 해설이 **매달 건너뛰고 두 달에 한 번** 돕니다 (2026-10-07)

**보내는 곳**: ax-sub → bds · **작성**: 2026-10-07
**요지**: *"월간 AI 해설 54.7일 경과"* 가 몇 주째 반복된 **근본 원인**을 찾았습니다. 설정 하나입니다.

---

## 1. 증상 — 아시던 그것입니다

감시견이 이 문장을 반복해 왔습니다.

```
데이터 신선도 점검: "월간 AI 해설 54.7일 경과" (한도 45일)
                   "월간 AI 해설 57.8일 경과"
```

**45일 한도인데 54.7일·57.8일이 나옵니다.** 월 1회 크론인데 왜 두 달 치가 쌓이는가 —
지금까지 "배치가 실패해서" 로 설명돼 왔는데, **실패가 아니라 설계였습니다.**

---

## 2. 원인 — `STALE_DAYS(35)` 가 **크론 간격(28~31일)보다 깁니다**

```
scripts/generate-complex-commentary.ts:245   const STALE_DAYS = 35
supabase/.../complex_commentary_inputs_rpc.sql:119
        OR pr.ai_cached_at < NOW() - (p_stale_days || ' days')::interval
```

RPC 는 **35일보다 오래된 행만** 돌려줍니다. 그런데 크론은 매월 1일입니다.

| 10-01 생성한 행 | 나이 | RPC 판정 | 신선도 점검(한도 45일) |
|---|---|---|---|
| **11-01 크론** | **31일** | **아직 신선 → 안 돌려줌** | 정상 |
| 11-15 | 45일 | stale | 경계 |
| **12-01 크론** | **61일** | stale → 재생성 | 🔴 **한도 초과** |

> **11-01 크론은 할 일이 없다고 판단하고 그냥 끝납니다(31 < 35).**
> 다음 재생성은 **12-01**이고, 그 사이 **11-15부터 약 16일간 신선도 점검이 빨강**입니다.
> 실측으로 나온 54.7일·57.8일이 정확히 이 구간입니다.

**실패한 적이 없습니다. 매달 한 번씩 조용히 건너뛴 것입니다.**

---

## 3. 그런데 단순히 `STALE_DAYS` 만 줄이면 안 됩니다

`STALE_DAYS` 를 25로 낮추면 매달 전량이 stale 이 됩니다. 그런데 —

```
창원 대상        ~612건   (tx_count_30d > 0)
하루 TPD 예산    ~408건   (200K / 490토큰)
```

**한 번에 안 찹니다.** 월 1회 크론으로는 구조적으로 불가능합니다.

---

## 4. 제안 — **크론을 매일로 바꾸고 `STALE_DAYS` 를 25로**

```diff
- - cron: '0 20 1 * *'    # 매월 1일
+ - cron: '0 20 * * *'    # 매일
```
```diff
- const STALE_DAYS = 35
+ const STALE_DAYS = 25
```

**staleness 필터가 곧 커서입니다.** 별도 이어받기 구현이 필요 없습니다.

| 날 | 일어나는 일 |
|---|---|
| 1일차 | stale 612건 중 ~408건 처리, TPD 소진 |
| 2일차 | 남은 ~204건 처리. 완료 |
| 3~25일차 | stale 0건 → **즉시 종료**(TPD 거의 안 씀) |
| 26일차~ | 다시 stale 이 생기며 자연스럽게 순환 |

| | |
|---|---|
| 신선도 | 최대 ~27일. **한도 45일 안에 항상 들어옵니다** |
| TPD 충돌 | **사라집니다.** 할 일 없는 날은 토큰을 안 씁니다 — 수·금·일 회피를 고민할 필요가 없어집니다 |
| 이어받기 구현 | **불필요.** `(b) 일별 분할 이어받기` 로 보류하셨던 것이 공짜로 해결됩니다 |
| 변경량 | **2줄** |

### 한 가지 같이 봐 주실 것 — `exit(1)`

지금은 TPD 소진 시 `exit(1)` 이라 워크플로가 빨강이 됩니다(`:393`).
매일 돌리면 **따라잡는 1~2일차마다 빨강**이 뜹니다. 그런데 그건 **정상 동작**입니다.

`data_sources` 가 이미 `partial` + `reason` 으로 사유를 싣고 있으므로,
**TPD 소진은 `exit(0)` 으로 두고 `failed > 0` 일 때만 `exit(1)`** 로 하시는 게 맞아 보입니다.
안 그러면 또 "매일 켜지는 빨강" 이 생기고, 그건 아무도 안 보게 됩니다.

**판단은 맡기겠습니다** — 빨강을 유지하시려면 저희 감시견이 그 워크플로를
"따라잡는 중이면 정상" 으로 읽도록 프롬프트에 적겠습니다. 어느 쪽인지만 알려주세요.
