  확정지번 술어(주석은 맞고 코드가 틀림) · 역지오코딩 가드(동만 봄) · K-apt 필드명 폴백

- **상류 API 는 버전 단위로 폐기된다.** 진단 정보를 가진 경로(에러 봉투 분류기)와
  필요한 경로(비2xx)가 엇갈려 있으면 답이 본문에 있어도 못 본다
- **감시 규약에는 그 규약을 지킬 도구가 딸려야 한다.** "개별 단지를 특정한 뒤에만
  기준선을 올린다" 는 옳았지만 특정할 방법이 없어 지켜지지 않았다
- **가드는 실제로 일한다** — kaptAddr 621건에서 기형 0건, 보류 11건이 전부 진짜 문제였다
- **순환을 조심한다** — 좌표가 주소에서 나왔으면 "좌표가 주소 쪽에 있다" 는 동어반복이다.
  독립 근거(K-apt · 이름 충돌 · 카카오 거리)를 층으로 쌓아야 한다
- **파싱하지 말고 재구성한다** — 시군구를 이미 아는데 상류 문자열을 파싱할 이유가 없다

## 🔧 운영 이슈 — 승인 규칙이 구조적으로 불가능하다

브랜치 보호가 `1 approving review` 를 요구하는데 **GitHub 은 PR 작성자의 자기 승인을 막는다.**
1인 저장소라 작성자 = 소유자이므로 **만족시킬 방법이 없고** 매번 `--admin` 으로 뚫어야 한다.
그러면 규칙이 이름만 남는다.

권고: `required_approving_review_count` 를 빼고 **필수 상태검사 4개는 유지**한다.
검사는 실제로 만족 가능하고 값을 낸다(오늘 #4 의 5/5 통과가 그 증거다). — **미결**

또 하나: **스택 PR 머지 시 base 브랜치를 지우면 안 된다.** GitHub 이 재지정하지 않고
PR 을 닫아버린다(#2·#5 가 그렇게 닫혔고 새로 올려야 했다). rebase 머지가 SHA 를 다시 쓰므로
남은 브랜치는 `git rebase origin/main` 으로 중복을 걷어내야 한다.
