## 결정: **1번 (고쳐서 살리기)**

제안하신 것 — **건축HUB 단계 제거 · 대상을 창원·김해로 되돌림 · 주소 모르면 미적재 · `[runstat]`** —
그대로 좋습니다. 아래 둘만 더해 주세요.

### ⓐ 기존 116행을 비우고 시작해 주세요

진단의 핵심이 *"들어가 봐도 승인할 게 없는 상태"*였습니다.
**그런데 고쳐도 그 116행은 큐에 그대로 남습니다.**
새로 들어오는 깨끗한 1~2건이 쓰레기 116건에 묻히면 **같은 일이 그대로 반복됩니다.**

```
기존 116행 → status = 'rejected' 로 일괄 전환
행은 지우지 않습니다. 상태만 바꿉니다 (기록으로 남겨 주세요)
admin_notes 에 사유를 한 줄 남겨 주시면 좋겠습니다
  예: "2026-10-14 일괄 거절 — 07-06 지역 회귀(2aa2153)로 수집된 대상 외 건"
```

이게 빠지면 1번은 실패합니다. **검수 화면이 있어도 9주간 아무도 안 들어간 이유가
바로 큐 상태였기 때문**입니다.

### ⓑ 판단일과 판정식을 **지금** 정합니다

9주를 흘려보낸 진짜 이유는 버그가 아닙니다.
**아무도 "언제 판단할지"를 안 정했기 때문**입니다. 고치기만 하면 또 흘러갑니다.

```
판단일   2026-11-09 (수정 후 4회 발화: 10-19 · 10-26 · 11-02 · 11-09)

볼 것    (a) 창원·김해 적재 건수
         (b) confirmed_at 이 채워진 건수

판정     a>0, b>0  → 유지
         a>0, b=0  → 수집은 되는데 아무도 안 쓴다      → 중단
         a=0       → 창원에 분양 뉴스가 사실상 없다     → 소스 자체 재검토
```

**(a)와 (b)를 나눈 이유**: *"수집이 안 된다"*와 *"수집은 되는데 안 쓴다"*는
**다른 고장이고 조치가 정반대**입니다. 한 숫자로 보면 구분이 안 됩니다.

**부탁**: `[runstat]` 에 **창원·김해 건수를 따로** 찍어 주세요.
그러면 11-09에 로그만 보고 판정할 수 있고, DB를 따로 안 뒤져도 됩니다.

```
[runstat] job=crawl-presale-news status=ok items=N target=M
          (items = 감지 전체, target = 창원·김해 적재분)
```

## 기대치 — 고치고 나면 **주당 0~1건**이 정상입니다

지금 116행에 "대상 축소 + 주소 없으면 미적재"를 적용하면 **살아남는 게 3건 이하**입니다.

```
주소 기준          행
경남 아님          39     → 대상 외
경남(창원 외)       2
창원               1
주소 없음          74     → 미적재
```

**이건 고장이 아니라 창원 분양 뉴스의 실제 양입니다.**
0건이어도 보고만 되면 정상입니다(원칙 5 — 산출물 0건도 보고한다).
**0건을 실패로 읽지 않도록** `[runstat]`에 꼭 찍어 주세요.

## 왜 2번·3번이 아닌지 (참고)

**2번(건축HUB만 제거)은 가장 나쁩니다.** 타임아웃은 사라지지만 쓰레기가 계속 쌓이고,
큐가 더러운 채로 남아 ⓐ 문제가 영구화됩니다.

**3번(중단)은 지금은 이릅니다.** 버그 3개가 전부 식별됐고 고치는 비용이 작습니다.
*"고쳐 본 적 없이 접는 것"*과 *"고치고도 안 쓰여서 접는 것"*은 기록으로서 가치가 다릅니다.

> 🔴 **다만 ⓑ 가 없으면 3번이 맞습니다. 기한 없는 1번은 3번보다 나쁩니다** —
> 고쳤다는 안도감만 주고 같은 자리에 다시 서게 됩니다.
