## 🔴 남은 확인 2건 — 날짜가 박혀 있다

### 1. 9/28(월) 크론 — `09-07~09-13` 주가 덮어써지나

지금 그 행은 **옛 방식(D+0)으로 만들어진 것**이다. 아직 안 고쳤다 —
오늘(D+10) 다시 만들면 같은 버그를 재생산하기 때문이다.

```sql
select period_start, sgg_code, generated_at,
       (input_snapshot->>'txCount')::int as 건수,
       (input_snapshot->>'txCount')::int - (input_snapshot->>'prevTxCount')::int as 증감
from regional_commentary
where period_type='weekly' and period_start = '2026-09-07';
```

| 볼 것 | 기대 |
|---|---|
| `generated_at` | **2026-09-28** 로 바뀐다 |
| 건수 | 늘어난다(D+0 → D+15) — 진해구는 6 → 18 근처 |
| 로그 | `주 종료 후 15일 경과` |

## ⚠️ 앞으로 조심할 것

### `--week-start` 는 성숙도 가드를 **완전히 우회한다**

`main()` 의 ㉘ 가드는 `!weekStartArg` 일 때만 작동한다.

```ts
if (!weekStartArg && periodEnd >= todayStr) { /* 건너뜀 */ }
```

그래서 **workflow_dispatch UI 에 최근 주를 입력하면 D+1 상태로 생성된다** —
§41 버그가 그대로 재발한다. 지금 있는 건 경고 로그 한 줄뿐이고 막지는 않는다.

```
⚠ 경과일 3일은 15일 미만이라 거래량 증감 방향이 10% 이상 틀릴 수 있다.
```

과거 주 보충에는 이 우회가 필요하니 없애면 안 된다. **다만 경고로 충분한지는 다시 봐야 한다** —
CI 로그 한 줄은 아무도 안 본다는 걸 §42 에서 이미 배웠다.
(제안: `--force-immature` 같은 명시 플래그 없이는 D+15 미만을 거부)

**이번 세션에서는 안 고쳤다.** 이미 세 건을 고쳤고, 사람이 손으로 일으켜야 하는 경로라
급하지 않다고 봤다. 판단은 다음 사람 몫이다.

### 저장소 간 상수 결합 — 아무도 강제하지 않는다

`REPORTING_LAG_WEEKS`(여기) ↔ `EXPECTED_LAG_WEEKS`(`realtrade-story`)

그쪽은 이 값으로 **"몇 주까지가 정상이고 그 뒤부터 고장인가"** 를 판정해 홈 카드에
경고를 띄운다. 여기만 키우면 **매주 영구히 경고가 켜지고**(2026-09-23 에 실제로
그럴 뻔했다), 여기만 줄이면 진짜 고장을 정상이라 부른다.

지금 장치는 **양쪽 주석이 서로를 가리키는 것**뿐이다. 이 값을 건드리면 그쪽에 알려라.

### 관찰 — Actions 발화 지연이 늘고 있다

크론은 `0 21 * * 0`(일 21:00 UTC)인데 실제 발화가 밀린다.

| 시기 | 지연 |
|---|---|
| 8월 (4회) | 12~47분 |
| 9월 (4회) | **1시간 49분 ~ 2시간 20분** |

**지금은 무해하다** — 15일 여유가 있어 2시간쯤은 아무 영향이 없다.
오히려 이 여유가 지연에 둔감해진 부수 효과다. 다만 **추세가 한 방향**이라 적어둔다.

## 이미 나간 것은 고쳤다

9주 54행 중 성숙한 **7주 42행을 재생성**했다(방향 뒤집힘 3건, 침묵 전환 14건).
가장 크게 틀렸던 것: `8/31 성산구 — 발표 27건, 실제 73건`.
달 넘는 두 주(`7/27~8/2`, `8/31~9/6`)는 §42 수정 뒤 한 번 더 돌려 템플릿을 걷어냈다.

재생성 전 54행 전량 백업은 **세션 스크래치패드에만 있다**(리포에 안 들어갔다).
되돌릴 일이 생기면 `regional_commentary` 는 `upsert` 라 `--week-start` 로 다시 만들면 된다.
