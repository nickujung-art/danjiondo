<objective>
Phase 37이 남긴 gap 1건과 이월 관찰 2건을 닫고, 신규 RLS 규약을 문서화한다.

Purpose:
- **HARD-02** — `20260619000003_recommend_hagwon_candidates_v2.sql`이 `LANGUAGE sql`로
  `hagwon_db.blog_tags`·`blog_snippet`을 SELECT하는데 그 컬럼을 만드는 `ADD COLUMN` DDL이 로컬에 없다.
  Postgres는 `check_function_bodies=on`(기본값)에서 SQL 함수 본문을 **CREATE 시점에 검증**하므로
  `supabase db reset`이 그 지점에서 실패한다. Phase 37은 `migration list`·`db push --dry-run`만
  돌렸고 그 둘은 **파일을 실행하지 않으므로** 이 결함을 못 잡았다 → `gaps_found` 판정.
  이번에는 **`supabase db reset`을 실제로 실행하는 것이 유일한 합격 기준**이다.
- **HARD-03** — `recommend_hagwons` 오버로드 2개 공존. `phase28_subject_v2`가 인자를 배열화하며
  구버전을 DROP하지 않았다. 인자 미명시 호출 시 모호성 에러 위험. 앱 호출부 0건 확인됨.
- **HARD-04** — 신규 RLS 정책 `TO` 절 명시 규약을 `CLAUDE.md`에 추가한다. **규약 문장 추가일 뿐이며
  기존 96개 정책의 일괄 수정은 명시적으로 범위 밖이다** (D-04).

Output: 마이그레이션 파일 재배치 1쌍 + DDL 복원 1개 + DROP 마이그레이션 1개 +
`CLAUDE.md` 규약 1줄 + **`supabase db reset` 실측 결과(성공 또는 미검증 사유)**.

⚠️ **HARD-02는 프로덕션 스키마를 바꾸지 않는다.** 복원 DDL이 `ADD COLUMN IF NOT EXISTS`이고
프로덕션엔 두 컬럼이 이미 존재하므로 재적용은 no-op다. 게다가 이 파일은 `repair --status applied`로
원장에 기록되어 **push 대상에서 아예 빠진다.** 즉 HARD-02가 고치는 것은 **로컬 재현성뿐**이다.
"적용했는데 스키마가 안 변했다"고 당황하지 말 것 — 그게 정상이다.
이 plan에서 프로덕션에 실제로 적용되는 것은 HARD-03의 DROP 마이그레이션 1개뿐이다.
