<objective>
`storage.objects`의 `ad_images_service_write` 정책에 역할 검사가 없어 **anon 키 보유자가
`ad-images` 버킷(`public=true`)에 임의 파일을 업로드할 수 있는** 취약점을 닫는다.

Purpose: 이 정책은 `roles={public}` + `with check (bucket_id = 'ad-images')`뿐이다.
어드민 업로드는 `src/lib/auth/ad-actions.ts`의 Server Action이 service_role로 수행하는데,
service_role은 `BYPASSRLS`라 이 정책의 적용을 아예 받지 않는다. 즉 **이 정책이 존재해서 생기는
유일한 효과가 "비-service_role(anon 포함) 업로드 허용"이며 그게 정확히 취약점이다.**
같은 저장소의 `realtor_profiles_service_insert`·`cardnews-payloads service insert`는
`auth.role() = 'service_role'` 조건을 갖고 있어 이것은 관행이 아니라 단독 실수다.

Output: 버킷·정책 2개의 최초 로컬 마이그레이션 1개 + anon 실측 검증 스크립트 1개 +
프로덕션 적용(`npm run db:push`) + 수정 전/후 실측 대조 결과.

  `deny`는 수정 후 기대값이며, 항목 1의 PASS 판정이 이 인자를 따른다. 인자 누락 시 `deny`.

  1. **anon 업로드** — `anon.storage.from('ad-images').upload(...)`. `--expect=deny`면 에러(RLS 위반,

     성공한 경우 반환 경로를 cleanup 목록에 반드시 등록한다.
  2. **anon 기존 파일 읽기 [positive control]** — baseline 파일 목록(admin `list()`로 조회한

     baseline 파일이 0개면 이 항목은 SKIP이 아니라 FAIL로 처리하고 사유를 출력한다.

  4. **버킷 파일 감사** — admin `list()` 결과에서 `PREFIX`가 아닌 파일 전부의 `name`·`created_at`·
