**소급 대상 3회차 — 재현 인자 (플래너가 `getWeekCode`/`getWeekLabel` 로 검증)**
```
2026-W24 : --from=2026-06-14 --to=2026-06-20   → weekCode "2026-W24", weekLabel "2026년 6월 2주차"
2026-W25 : --from=2026-06-21 --to=2026-06-27   → weekCode "2026-W25", weekLabel "2026년 6월 3주차"
2026-05  : --month=2026-05                      → weekCode "2026-05",  weekLabel "2026년 5월 전체"
```
🔴 W24·W25의 weekLabel은 아카이브 HTML의 `WEEKLY REPORT · …` 문자열과 **정확히 일치**한다
(`2026년 6월 2주차` / `2026년 6월 3주차` — 플래너가 grep으로 확인). 인자가 맞다는 증거다.

**`2026-05`의 함정**: `--month` 경로는 `weekLabel = "2026년 5월 전체"` 를 만든다
(`generate.js:136-138`). HTML이 0개라 대조할 원본이 없다.

**비교에 쓸 수 있는 원본 — 회차별로 다르다**
| 회차 | 대조 가능한 원본 | 방법 |
|---|---|---|
| `2026-W24` | HTML **12개** (`59-jinhae`·`84-seongsan`·`84-uichang`) + PNG 74 | HTML의 순위·가격 텍스트를 파싱해 대조 |
| `2026-W25` | HTML **4개** (`city-overall`) | 동일 |
| `2026-05` | **PNG 4개뿐** | 🔴 텍스트 대조 불가. 사람이 PNG를 눈으로 봐야 한다 |

🔴 아카이브 HTML은 **디자인이 드리프트**돼 있다(40-01 실측). 하지만 **데이터 값**
(단지명·가격·순위)은 그대로 들어 있으므로 **값 비교에는 쓸 수 있다.**
디자인 바이트 대조에 쓰지 말 것 — 그건 40-01이 이미 배제했다.

**HTML에서 값을 뽑는 최소 방법 (정규식으로 충분)**
```
순위 행:  <div class="row-complex[^"]*">([^<]*)</div>   … <div class="row-price[^"]*">([^<]*)</div>
TOP3:     <div class="complex-name[^"]*">([^<]*)</div>  … <div class="price-num[^"]*">([^<]*)</div>
```
⛔ 이 파싱은 **비교 보고 전용 일회성**이다. `persist-contents.js` 나 제품 코드에 넣지 않는다
(D-02: "HTML 파싱은 템플릿 마크업에 결합돼 깨지기 쉽다").

**`generate.js` 플래그 (40-01·40-03 적용 후)**
`--series` `--dry-run` `--from` `--to` `--month` `--out` `--dump-data` `--data` `--persist`
