부산 16개 구 국토부 실거래가 10년 백필의 1일차 GitHub Actions 실행을 자동 트리거했다.   </what-built>
  <how-to-verify>
1. 오늘 실행 상태 확인: `gh run list --workflow=molit-backfill-once.yml --limit=1`
2. 남은 미완료 조합 확인:
   ```sql
   select sgg_code, count(*) filter (where status='success') as done
   from ingest_runs
   where source_id in ('molit_trade','molit_villa_trade') and sgg_code like '26%'
   group by sgg_code order by sgg_code;
   ```
3. **[D-04 필수] 각 일자 배치 완료마다 DB 용량 체크:**
   ```sql
   select pg_size_pretty(pg_database_size(current_database())) as total_db_size;
   ```
   - **< 450MB**: 미완료 구가 남아있으면 다음 영업일(04:00 KST 회피) 재트리거 — `--resume` 자동 적용:
     ```bash
     gh workflow run molit-backfill-once.yml \
       -f sgg_codes=26110,26140,26170,26200,26230,26260,26290,26320,26350,26380,26410,26440,26470,26500,26530,26710
     ```
   - **>= 450MB (경고 임계)**: 백필을 일시 중단하고 **즉시 사용자에게 보고**. 그 자리에서 다음 중 하나를 결정:
     - (a) `VACUUM FULL transactions` 재실행(33-08 선례: 271MB→202MB로 축소된 이력) 후 백필 재개
     - (b) Supabase Pro 전환(34-09에서 최종 결정하지만, 450MB 경고 시점에 앞당겨 결정 가능)
   - **>= 490MB (위험 임계)**: 500MB 초과 쓰기 실패(서비스 장애) 직전 — 백필 즉시 중단, VACUUM FULL 또는 Pro 전환 없이는 재개 금지
4. 모든 구가 완료(성공 또는 해당 월 데이터 없음)될 때까지 재트리거를 반복하며, 매 배치마다 3번 용량 체크를 수행한다.
  </how-to-verify>
  <resume-signal>모든 16개 구의 ingest_runs가 완료되고 최종 DB 용량이 기록되면 "백필 완료, DB N MB"라고 응답. 450MB 도달 시 "450MB 경고 — VACUUM FULL 실행함 / Pro 전환 결정 필요"로 대응 내역을 알려주면 다음 세션에서 이어서 진행한다. 진행 중이면 "N일차, M개 구 남음, DB N MB"로 알려준다.</resume-signal>
