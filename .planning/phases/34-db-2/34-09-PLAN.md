아래 SQL을 Supabase MCP(`execute_sql`, 우선) 또는 `psql "$SUPABASE_DB_URL"`로 실행해 전체 DB 용량과 주요 테이블별 용량(인덱스 포함)을 측정한다:
```sql
-- 전체 DB 용량 (인덱스·TOAST 포함, 500MB 한도와 직접 비교)
select pg_size_pretty(pg_database_size(current_database())) as total_db_size;

-- 주요 테이블별 용량 (테이블+인덱스+TOAST) 큰 순
select relname as table_name,
  pg_size_pretty(pg_total_relation_size(relid)) as total_size,
  pg_size_pretty(pg_relation_size(relid)) as table_only_size,
  pg_size_pretty(pg_indexes_size(relid)) as index_size
from pg_catalog.pg_statio_user_tables
order by pg_total_relation_size(relid) desc limit 10;

-- 부산 확장 기여분 추정 (지역별 거래 분포)
select left(sgg_code,2) as sido, count(*) as tx_count
from transactions group by left(sgg_code,2) order by tx_count desc;
```
측정값을 임계값과 비교:
- < 400MB: 무료 티어 여유 있음
- 400~500MB: 무료 근접, 35 phase(울산) 전 Pro 검토 필요
- > 500MB: 초과 확실, Pro 전환 필수 (또는 VACUUM FULL로 임시 축소)

부산 백필 전(34-06 기준선)·후 용량 차이를 계산해 "부산 순증가분"을 SUMMARY에 기록(35 phase 울산 용량 추정 근거).
