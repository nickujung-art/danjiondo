Purpose (39-CONTEXT F-05 요구사항 그대로):
- `src/` 전체에서 `.upsert(…, { onConflict: '…' })` 호출을 **정적 수집**한다.
  하드코딩 목록으로 하면 신규 upsert가 게이트를 그냥 빠져나간다.

  `pg_index.indpred IS NOT NULL`이면 추론 불가로 처리한다.

**39-02가 만든 RPC (호출 계약)**

```
public.unique_indexes_for_table(p_table text)
  → { index_name: string, columns: string[], is_partial: boolean, is_expression: boolean, is_valid: boolean }[]
```
- `columns`는 **attname 알파벳 정렬**로 온다. INCLUDE 컬럼은 제외(`indnkeyatts` 제한)
- **필터링은 하지 않는다** — 모든 UNIQUE 인덱스를 플래그와 함께 돌려준다. 제외 판정은 TS 담당
- `service_role` 전용 grant → 테스트의 `admin` 클라이언트로만 호출 가능
- `src/types/database.ts`에 타입이 없다 → 호출부에서 로컬 타입 + 캐스트로 처리한다.
  **`database.ts`를 재생성하지 않는다** (Phase 38 선례: 무관한 대규모 diff는 회귀 위험만 키운다)

실측 출력 예 (`p_table='favorites'`, 39-02 DROP **전** 프로덕션):
```
favorites_area_type_alert_unique_idx  {area_type_id,complex_id,site_id,user_id}  is_partial=true
favorites_complex_favorite_unique_idx {complex_id,site_id,user_id}               is_partial=true
favorites_pkey                        {id}                                       is_partial=false
```
→ `toInferrable`이 앞의 둘을 제거하면 남는 건 `{id}` 뿐이다. 그래서
`onConflict:'user_id,complex_id'`도 `'user_id,complex_id,site_id'`도 **둘 다 FAIL**이어야 한다.
**이것이 음성 대조 픽스처의 원본이다.**
